# Struct Scanning and NULLable Columns

> Bản dự án ELIMAZ CRM: bỏ phần sqlx (`db:` tag, `GetContext`, `SelectContext`); dùng mã sqlc sinh ra cho SQL tĩnh và `pgx.CollectRows` cho SQL trong `*_dynsql.go`. Chi tiết: `../SOURCE.md`.

## Static Queries: sqlc Generates the Structs

```sql
-- name: ListActiveUsers :many
SELECT id, name, email, deleted_at FROM users WHERE active = true;
```

sqlc generates a `User`-shaped row type and a method `ListActiveUsers(ctx) ([]ListActiveUsersRow, error)`; no hand-written scanning. Do not edit generated code (`**/internal/store/**`): change the `.sql` file and run `make gen`.

## Struct Scanning with pgx (dynamic SQL only)

With pgx (v5+), use `pgx.CollectRows` for automatic struct mapping in `*_dynsql.go` files:

```go
type User struct {
    ID        int64      `db:"id"` // pgx matches the db tag (or the field name, case-insensitive)
    Name      string     `db:"name"`
    Email     string     `db:"email"`
    DeletedAt *time.Time `db:"deleted_at"` // NULLable
}

rows, err := pool.Query(ctx, query, args...)
if err != nil {
    return fmt.Errorf("querying users: %w", err)
}
users, err := pgx.CollectRows(rows, pgx.RowToStructByName[User]) // closes rows
```

## JSON Marshaling

Database row types are not the API contract: in this project the HTTP request/response types are generated by ogen from `openapi.yaml`, and the handler maps row types to them. Keep `json` tags off database structs.

## NULLable Columns

Three approaches, from most to least recommended:

**1. Pointer fields (recommended for hand-written structs)** — clean, works with JSON marshaling:

```go
type User struct {
    ID        int64
    Name      string
    DeletedAt *time.Time // nil when NULL
}
// Check: if user.DeletedAt != nil { ... }
```

**2. `pgtype` types** (sqlc's default for nullable columns with pgx) — explicit `Valid` flag:

```go
type User struct {
    ID  int64
    Bio pgtype.Text
}
// Check: if user.Bio.Valid { use(user.Bio.String) }
```

sqlc can be configured to emit pointers instead (`emit_pointers_for_null_types`); follow the repo's `sqlc.yaml`.

**3. `COALESCE` in SQL** — moves NULL handling to the query:

```sql
SELECT id, COALESCE(bio, '') AS bio FROM users WHERE id = $1
```
